# Architecture

Status as of 2026-10-15: a localhost-only prototype. What is implemented is described as such;
anything marked **Proposed** is a direction, not a commitment. The prototype itself is described in
[prototype.md](prototype.md). P0, P1 and P2 are development milestones here, not approval gates.

## Decisions in force

- **Localhost only.** `dev` and `start` bind to `127.0.0.1`; `src/proxy.ts` answers 403 to any
  other `Host`. Neither is authentication. See prototype.md, section 8.
- **Cache Components and Partial Prefetching are enabled.** These are the defaults generated by
  `create-next-app@16.4.1` and are kept as-is (`next.config.ts`). Today `/`, `/workspace`, `/globe` and
  `/geo/boundaries.json` are prerendered at build time from files read once at module scope in
  `dataset.server.ts` and `overlay.server.ts`, so a data rebuild needs a server restart (dev) or a new build (production).
  `/geo/globe-boundaries.json` is dynamic: it re-checks the globe's file on every request.
- **Generated data is server-only.** Everything `data:build` writes goes to `data/generated/`.
  Nothing is written to `public/`, which Next.js serves verbatim; a guard test fails if a data file
  appears there. The boundary layer reaches the browser through the route handler
  `src/app/geo/boundaries.json/route.ts`, and the browser validates it before drawing.
- **Boundaries are provisional and attributed.** A layer must carry licence, attribution, source
  snapshot and a status beginning "Provisional", or the browser refuses it. A name match between a
  workbook row and an official block is a `provisional` link, never described as verified.
- **Four things are kept apart:** sales territory (the workbook `DISTRICT` label), official unit
  (LGD), the crosswalk link between them, and boundary geometry. The `DISTRICT` label is never an
  input to geographic matching.
- **The globe is a navigation entry, not the entry.** `/globe` is in the primary navigation (Globe, Overview, Workspace) as a
  local prototype; `/` stays the Territory Overview. `/globe-prototype` redirects to `/globe` (307). A place selected on the
  globe opens in the 2D workspace through a URL hash built from validated IDs (`features/globe/workspace-link.ts`,
  `#feature=` for a district or block, `#unit=` for a workbook row, none for the state): no shared selection store. Three.js is
  imported only inside `features/globe` and loaded only by `/globe`. The outlines remain provisional and unofficial; see
  [globe-prototype.md](globe-prototype.md). The Overview also carries an "Explore on the globe" card between its heading and
  the dashboard (`components/dashboard/GlobeEntryCard`): a server component with no props and no import from
  `features/globe`, so it renders whether or not the data is built and the homepage still downloads no Three.js, texture or
  outline file. It is two plain links (`/globe`, `/workspace`) with the default Next.js prefetching and carries no figures.
- **Selection is by internal ID only** (`TU-`, `GB-`, `GD-`, `ST-`), never by name or label.
- **Allocation states are kept apart:** allocated, confirmed unallocated, missing / unverified,
  conflicting. A missing record is never read as unallocated. `Vacant` is a slot-level marker, not a
  block state, until an approved-position source exists. The set is provisional (B-12, B-28) and its
  rules sit in `src/features/territory/state.ts`.
- **Tailwind 4 is wired through `@tailwindcss/turbopack`** (a template default), so there is no
  `postcss.config`. Builds use Turbopack.
- **ESLint stays on 9.x.** ESLint 10 needs peer-dependency overrides with the plugins bundled in
  `eslint-config-next`; revisit when they declare support.
- **Tests use Node's built-in runner.** Node 22.18+ runs TypeScript directly, so no test dependency
  was added. Pure modules in `src/features/geo/*.ts` and `src/features/territory/*.ts` import each
  other with `.ts` extensions for this reason (`allowImportingTsExtensions`), and are shared by the
  scripts, the app and the tests.
- **One network use.** `scripts/fetch-osm.mts` is the only code that contacts an external service,
  with a generic User-Agent and a geographic query only. The production `dependencies` in `package.json` are exactly
  `next`, `react`, `react-dom` and `three` (`three` is the globe's renderer, at an exact version). `tests/guardrails.test.ts`
  fails if that set changes, and requires `three`'s version to be exact. Build, lint, type and test tooling is under
  `devDependencies`, not in that set.

## Source layout

```text
src/app/                 Routes (/, /workspace, /globe, /geo/boundaries.json, /geo/globe-boundaries.json), root layout, globals.css (design tokens), icon.svg
src/proxy.ts             Loopback Host check, runs for every request
src/components/layout/   AppShell, TopNav, PageHeader, NavLink
src/components/ui/       Badge, Card, LogoMark (domain-agnostic primitives)
src/components/dashboard/ KpiCard, MapWorkspace (frame)
src/features/territory/  Domain types, allocation-state rules, model, selection, server data access, UI
src/features/geo/        Name matching, crosswalk, geometry, OSM linking, layer encoding, viewport maths
src/features/allocation/ Append-only local change log: reducer, validation, browser storage
src/features/globe/      The 3D globe (Three.js, lazy): renderer, outline validation, details panel, hand-off to the workspace
src/lib/                 cn(), site config and navigation, loopback host check
scripts/                 Data pipeline and build-output scans
data/                    Generated and fetched data (git-ignored)
tests/                   unit/, e2e/, guardrails.test.ts
```

Convention: `components/` holds presentational pieces with no domain logic. Domain logic, data access
and feature-specific UI live under `features/<name>/`.

The Gate P0 code (`src/features/map/`, `src/app/territory-map/`, two unused dashboard components,
`tests/fixtures/` and six test files) was removed on 2026-10-15; prototype.md, section 10, records
what and where the backup is. `/territory-map` only redirects to `/workspace`, and `/globe-prototype` only redirects to `/globe` (`next.config.ts`).

## Explicitly out of scope so far

No database or migrations, no Supabase or Power BI integration, no authentication or access control,
no shared allocation store (changes live in one browser), no managed import (the workbook is read
by an offline script), no ward or urban-body geography, and no deployment. **Salary data is excluded
from the platform's scope.** Staff names are present in the local dataset (B-25 is open) and must
stay on this machine. The served `/globe` page carries none; the globe's block details fetch the selected block's workbook rows
from `POST /api/globe/block-rows` on demand, so the same applies to that response.

## Open questions

Tracked in [data-audit/open-business-decisions.md](data-audit/open-business-decisions.md). The ones
that most affect the architecture:

1. **Legal:** ODbL use of OpenStreetMap outlines for internal multi-user use, and LGD reuse (B-18).
2. **Geography:** which authoritative boundary source, if any, replaces the provisional outlines; how
   wards in Kolkata and Howrah are handled (B-20, B-06).
3. **Allocation model:** what counts as allocated, vacant and white space (B-12, B-28), and who
   signs off the crosswalk (B-26).
4. **Hosting and access:** whether Supabase or self-hosted PostgreSQL/PostGIS, who may see or edit
   what, and what must change before staff names leave this machine (B-15, B-16, B-25).
5. **Power BI:** embedding model, licensing, and how embedded reports receive territory filters.
